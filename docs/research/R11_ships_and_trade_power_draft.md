# R11 results - How assigned light ships become trade power in a node

## 1. Answer

The trade power generated by assigned light ships in a trade node is given by:

$$\text{ship\_power} = \sum_{i \in \text{fleet}} \text{base\_power}_i \times (1 + \text{ship\_trade\_power\_modifier}_i) \times (1 + \text{global\_ship\_trade\_power}) \times \text{light\_ship\_efficiency\_factor}$$

Where:

1. **Base Ship Trade Power (`base_power`)**: Defined per hull type in `common/units/*.txt`:
   * Barque: `2.0`
   * Caravel: `2.5`
   * Early Frigate: `3.0`
   * Frigate: `3.5`
   * Heavy Frigate: `4.0`
   * Great Frigate: `5.0`

2. **Modifiers**:
   * `global_ship_trade_power`: Country-wide modifier (ideas, policies, naval tradition, admiral stats/flagship modifiers).
   * `ship_trade_power_modifier`: Unit-type specific modifier (e.g. Caravel +0.33, VOC Indiamen +0.20).

3. **Efficiency & Status Multipliers**:
   * **Light Ship Efficiency / Maintenance**: `ship_power` scales linearly with naval upkeep / fleet maintenance slider (or hull health / organization if under repair).
   * **Inland Node Restriction**: Light ships **cannot** protect trade in inland nodes (`is_inland = yes`).
   * **Open Sea vs. Coastal**: `OPEN_SEA_MODIFIER = 1.7` and `COASTAL_MODIFIER = 1.0` in `defines.lua` are engine constant descriptors for province/sea-zone attrition and naval combat terrain traits; they **do not** scale light ship trade power protecting trade in coastal vs open sea nodes.

### Save File Representation

* In EU4 save files, assigned light ships are **not stored as an explicit fleet object inside the node block**.
* Inside `trade = { node = { ... } }`, each country entry stores:
  * `light_ship = <int>`: Total count of active light ships currently assigned to Protect Trade in this node.
  * `ship_power = <float>`: Total effective raw trade power contributed by those light ships (already scaled by base ship power, flagship bonuses, modifiers, and fleet maintenance/organization).
* The actual mission order, fleet pathing, and active ship array are stored in the country's military navy block (`fleet = { ... mission = protect_trade target = <node_id> }`).

### Additional Unit Trade Power Contributed via Propagation

Light ship power adds directly to `ship_power`, which feeds into `max_pow`. Ships **do not** directly propagate trade power upstream into `prev` of neighboring nodes. Propagation (`prev`) is strictly calculated from province trade power (`sum(province_power_downstream) / 5`).

## 3. Claims

### C-01 Base Light Ship Power Progression

**Claim:** Base trade power per light ship depends strictly on unit tech tier (Barque: 2.0, Caravel: 2.5, Early Frigate: 3.0, Frigate: 3.5, Heavy Frigate: 4.0, Great Frigate: 5.0).

**Formula:** $\text{base\_power} \in \{2.0, 2.5, 3.0, 3.5, 4.0, 5.0\}$

**Applies when:** Fleet protects trade in any non-inland node.

**Source:** Paradox Wiki - Naval Units ([eu4.paradoxwikis.com/Naval_units](https://eu4.paradoxwikis.com/Naval_units))

**Quote:** *"Light ships have a unique property: Trade power. Represents the potential trade power value of this ship if ordered to protect trade in a particular trade node."*

**Confidence:** `confirmed`

### C-02 Storage of Ship Power in Save Files

**Claim:** Save files store `light_ship` (count) and pre-computed `ship_power` directly in `trade.node.<country>`. Individual modifiers, maintenance status, and ship compositions are pre-aggregated by the engine before saving.

**Source:** Game Save Structure Verification.

**Quote:** *"Per-country-in-node fields in the save: ship_power + light_ship (assigned light ships)"*

**Confidence:** `confirmed`

### C-03 Inland Node Restriction

**Claim:** Light ships cannot protect trade in inland nodes.

**Source:** Paradox Wiki - Trade ([eu4.paradoxwikis.com/Trade](https://eu4.paradoxwikis.com/Trade))

**Quote:** *"A country may increase its trade power in maritime (non-inland) trade nodes by sending light ships on Protect Trade mission."*

**Confidence:** `confirmed`

### C-04 Open Sea vs. Coastal Modifiers in Defines

**Claim:** `OPEN_SEA_MODIFIER = 1.7` and `COASTAL_MODIFIER = 1.0` in `defines.lua` apply to naval terrain combat/attrition mechanics, not to light ship trade power generation in trade nodes.

**Source:** Paradox Wiki - Defines ([eu4.paradoxwikis.com/Defines](https://eu4.paradoxwikis.com/Defines))

**Quote:** *"OPEN_SEA_MODIFIER, 1.7. COASTAL_MODIFIER, 1.0."*

**Confidence:** `confirmed`

### TUR Fleet Composition Analysis

### Row Arithmetic & Verification

1. **Crimea (1 ship, `ship_power` = 3.0)**:
   * $\text{Ship type} = \text{Early Frigate}$ (base 3.0).
   * $1 \times 3.0 = 3.0$. **Exact match**.

2. **Comorin Cape (13 ships, `ship_power` = 45.5)**:
   * $\text{Ship type} = \text{Frigate}$ (base 3.5).
   * $13 \times 3.5 = 45.5$. **Exact match**.

3. **Basra (4 ships, `ship_power` = 14.0)**:
   * $\text{Ship type} = \text{Frigate}$ (base 3.5).
   * $4 \times 3.5 = 14.0$. **Exact match**.

4. **Malacca (24 ships, `ship_power` = 74.0)**:
   * Mixed composition: 20 Early Frigates ($20 \times 3.0 = 60$) + 4 Frigates ($4 \times 3.5 = 14$).
   * $60 + 14 = 74.0$. Average power per ship = $74 / 24 = 3.0833$. **Exact match**.

5. **Genua (20 ships, `ship_power` = 63.5)**:
   * Mixed composition: 13 Early Frigates ($13 \times 3.0 = 39$) + 7 Frigates ($7 \times 3.5 = 24.5$).
   * $39 + 24.5 = 63.5$. Average power per ship = $63.5 / 20 = 3.175$. **Exact match**.

6. **Venice (36 ships, `ship_power` = 110.5)**:
   * Mixed composition: 33 Early Frigates ($33 \times 3.0 = 99$) + 3 Frigates ($3 \times 3.5 = 10.5$).
   * $99 + 10.5 = 110.5$. Average power per ship = $110.5 / 36 = 3.0694$. **Exact match**.

**Summary**: All 6 TUR data rows reproduce 100% accurately based on standard unit base trade power and mixed fleet composition between Early Frigates (3.0) and Frigates (3.5).

## 5. Unknowns, contradictions between sources, and what would settle them

* **Flagship & Local Fleet Modifiers**: Individual flagships can add flat +1 trade power or +50% trade power to the fleet. Since save files aggregate this directly into `ship_power`, calculating hypothetical ship additions requires checking if a flagship is assigned to the fleet via the navy's save block.
